# CPU/GPU 索引构建性能报告（2026-11-04）

本轮候选在两组本地 250K 输入上完成源码构建、完整 SQL 配对和重启验证：
128D 构建＋首查从 46.749 s 降到 4.481 s，256D 从 49.659 s 降到 6.978 s；
对应 10.432×、7.117×。Gaussian 256D Recall@10/100 从 0.950391/0.898320 提高到 0.999609/0.996121。
这些输入不是正式 SIFT250K/Hidden250K，不能据此宣称正式满分。

## 方法与计时边界

每版使用全新服务目录；先导入原始无索引表，从固定 CREATE VECTOR INDEX 到首条固定查询返回合法 ID 计时。
包含扫描、CPU/GPU 传输、原生 GPU 建图和同步、持久化以及首次重载；不包含源码编译、服务启动、导入、数据生成和真值计算。
GPU SQL 保持 `distance=l2,type=hnsw,lib=cuvs,m=16,ef_construction=200,ef_search=64`。

后续 Top-10 和 Top-100 各 4096 条单行近似 SQL，使用同一 libmysqlclient 连接；ID/Recall 检查在该组吞吐计时之后执行。
每条查询验证返回恰好 k 个互不重复且合法的外部 ID。两版输入、SQL、索引参数和环境相同，跨两组交换执行顺序。
真值按实际 FP32 输入计算 FP64 L2；向量用 9 位有效数字往返导入，外部 ID=`row_offset*17+1009`。

| 本地输入 | 生成方式 | 独立探针 | SQL 顺序 |
|---|---|---:|---|
| LocalClusters250K128 | seed=20261102，16 簇、16 维潜变量投影及小噪声 | 64，循环 64 次 | V5 → 候选 |
| LocalGaussian250K256 | 独立标准 Gaussian，base seed=20261104，query seed=20261105 | 256，循环 16 次 | 候选 → V5 |

NumPy 2.4.6、OPENBLAS_NUM_THREADS=8。256D 探针独立于最初筛选使用的 64 个探针；它们没有来自或推测隐藏数据。
重复探针的吞吐与正式 4096 个独立查询不同，样本 Recall 也不能保证其他数据分布上的质量。

## CPU VSAG 比较与回归

同一最终候选进程先初始化 GPU，再建立独立的 CPU VSAG 索引，输入与 128D GPU 配对相同。
CPU DDL 使用 m=16、ef_construction=200、ef_search=512；GPU 对外 SQL ef_search=64，内部 CAGRA 配置如前述。

| 实现 | 构建＋首查 / s | Top-10 QPS | Top-100 QPS | Recall@10 | Recall@100 |
|---|---:|---:|---:|---:|---:|
| CPU VSAG | 82.605 | 2837.767 | 1867.321 | 0.995313 | 0.985938 |
| V5 GPU | 46.749 | 141.428 | 136.892 | 1.000000 | 1.000000 |
| 候选 GPU | 4.481 | 994.081 | 808.855 | 1.000000 | 1.000000 |

CPU 查询更快，但本次配置与 Recall 不同；不把这些数字解释为严格同质量的 CPU/GPU 比值。
正式计分比较候选 GPU 与同轮 V5 GPU。另有公开 10K、CPU ef_search=64 回归：构建 2.657 s，
Recall@10/100 为 0.639917/0.652378，SQL 建表、建索引、查询及 ID 检查通过；CPU Recall 不作为 GPU 正式门槛。

## 筛选、GPU 与持久化证据

同轮 bridge 控制组是上一候选 aefeef34（NN_DESCENT 256/100，SINGLE_CTA/512）。
在 256D、256 个独立探针上，控制组建图＋首查 14.234 s、Recall 0.950781/0.898359；
入选方案 1.938 s、Recall 0.999609/0.996211。这是 bridge 边界，不能与完整 SQL 耗时混算。
12 项筛选、5 项最终 bridge 检查和真实最终源码的功能检查均保留。
未采用的 IVF-PQ、迭代 CAGRA、精确/混合精度建图等诊断原型不在生产编译中。

- Windows 与 Linux 主机测试通过：工作线程、800 并发同步提交、参数复位、内存错误、资源释放、快照损坏/截断和 OpenMP 显式偏好。
- 最终 bridge 公开 10K 真实 GPU 测试 Recall@10/100=1；单查、批量、并发、图导出/恢复逐边一致、输入所有权检查通过。
- 新进程读取 OBCUVS03，以及候选重载实际 V5 生成的 OBCUVS02 均通过；CPU 索引重启读取通过。
- rocprofv3 bridge 跟踪共 2686 个 kernel dispatch，包括 3 个 NN-descent local_join、1 个图 prune、128 个反向图 kernel 和 421 个 MULTI_CTA search kernel。
  它证明本次独立 bridge 实测执行真实 GPU 建图和搜索；并非完整 SQL 进程 profiler 认证。
- 本轮没有重跑完整 SQL profiler。此前 V5 与候选均在该镜像的 profiler 下于启动阶段退出，限制见上一版报告历史；
  正式 GPU 路径抽检仍须由组织方确认。普通 SQL、重启和独立 GPU profiler 本轮均成功。
